# BAZA — ERP/WMS frontend

Ролевой прототип оптового магазина и складского учёта на React, TypeScript, Mantine и React Router. Клиент оформляет заказ, сотрудники трёх складов собирают свои позиции, менеджер отгружает заказ, клиент подтверждает получение.

Текущие экраны работают с общим локальным хранилищем браузера. PHP из соседней папки `b2b` и подключение к БД не изменены и для запуска прототипа не нужны.

## Запуск

Требуется Node.js 22.18+ или 24 LTS.

```bash
npm ci
npm run dev
```

Откройте адрес, который выведет Vite. Настройка `.env` для нового прототипа не требуется. Маршруты используют `HashRouter`, например `/#/catalog` и `/#/orders`.

```bash
npm run build     # TypeScript и production-сборка
npm run preview   # просмотр собранного приложения
npm run lint      # статическая проверка
npm test          # автоматические проверки проекта
```

## Аккаунты для входа

У всех перечисленных аккаунтов пароль **`demo123`**. На экране входа можно выбрать роль и заполнить данные автоматически.

| Роль | Логин | Область работы |
| --- | --- | --- |
| Клиент | `client@test.com` | Магазин «У дома», каталог, корзина и собственные заказы |
| Сборщик № 1 | `worker1@test.com` | Склад напитков |
| Сборщик № 2 | `worker2@test.com` | Склад снеков |
| Сборщик № 3 | `worker3@test.com` | Склад бытовой химии |
| Менеджер | `manager@test.com` | Все заказы, сотрудники, передача и отгрузка |
| Администратор | `admin@test.com` | Пользователи, склады, товары и сброс демонстрации |

Это демонстрационные учётные записи. Роли и проверки доступа в этом прототипе выполняются на клиенте; подключение реальной авторизации и серверного хранения — отдельная интеграция.

## Проверка полного сценария

1. Войдите как `client@test.com`. В **Каталоге** добавьте хотя бы по одному товару со склада напитков, снеков и бытовой химии.
2. Откройте **Корзину**, проверьте количество, адрес, приоритет и комментарий. Нажмите **Проверить заказ**, затем **Подтвердить и оформить**. Сохраните номер открывшегося заказа. Остатки резервируются, а каждому задействованному складу создаётся отдельное задание.
3. Выйдите и последовательно войдите как `worker1@test.com`, `worker2@test.com`, `worker3@test.com`. В **Сборке заказов** откройте этот заказ, нажмите **Принять задачу**, затем **Начать сборку**. Для каждой позиции отметьте собранное количество и нажмите **Завершить сборку**.
4. После завершения всех складских заданий передайте заказ менеджеру кнопкой **Передать менеджеру**. Это действие доступно назначенному сборщику или менеджеру. При недостаче укажите её отдельно: она остаётся видна в заказе.
5. Войдите как `manager@test.com`, откройте заказ и подтвердите отгрузку. Заказ перейдёт в статус **Отправлен клиенту**.
6. Вернитесь в аккаунт клиента и подтвердите получение. Заказ перейдёт в статус **Завершён** и появится в истории.

Смена аккаунта не удаляет заказ и корзины других клиентов. Для просмотра уже подготовленных примеров в начальных данных есть заказы на разных этапах.

## Экраны

| Раздел | Маршрут | Доступ |
| --- | --- | --- |
| Вход | `/#/login` | Без авторизации |
| Обзор | `/#/dashboard` | Все роли, своя сводка |
| Каталог, корзина, профиль | `/#/catalog`, `/#/cart`, `/#/profile` | Клиент |
| Заказы и карточка заказа | `/#/orders`, `/#/orders/:id` | В пределах доступа роли |
| Задания на сборку | `/#/tasks` | Сборщик, назначенные склады |
| Карта складов | `/#/warehouses` | Сборщик, менеджер, администратор |
| Сотрудники | `/#/team` | Менеджер, администратор |
| Журнал событий | `/#/activity` | События, доступные текущей роли |
| Администрирование | `/#/admin` | Администратор и менеджер с выданными правами |

В каталоге доступны поиск, фильтры категории, склада и наличия, сортировка, карточка товара и количество для добавления. Корзина группируется по складам и повторно проверяет остатки при оформлении. Профиль позволяет изменить магазин, контактное лицо, телефон, email и адрес. Складская часть поддерживает принятие заданий, сборку, недостачу и передачу менеджеру. Администратор редактирует пользователей, назначения на склады, права, структуру складов, цены и остатки товаров.

## Сохранение и сброс данных

Пользователи, товары, остатки, корзины, заказы, уведомления, журнал событий и текущий аккаунт сохраняются в `localStorage` под ключом `wholesale-workspace-v1`. Перезагрузка страницы не сбрасывает прогресс. Вкладки одного браузера и адреса приложения используют общее состояние, включая текущую роль; проверять цепочку ролей удобно последовательным выходом и входом.

Для возвращения к исходным данным войдите как `admin@test.com`, откройте **Администрирование** и воспользуйтесь сбросом демоданных с подтверждением. Сброс заменяет локальные изменения начальным набором и оставляет вход администратора активным. Если браузер запрещает доступ к `localStorage`, изменения доступны только до перезагрузки.

Заказы существуют только в этом браузерном прототипе: обмена с реальными складами, оплатой или PHP нет. Изображения товаров и шрифты поставляются локально в `public/products` и `public/fonts`.

## Архитектура и сохранённая PHP-интеграция

Проект организован по FSD. Активные маршруты собираются в `src/app/App.tsx`; единая модель прототипа находится в `src/entities/wholesale`. Подробности слоёв, данных и переходов — в [docs/architecture.md](docs/architecture.md).

Ранее подготовленная интеграция PHP сохранена отдельно:

- `src/shared/api` — HTTP-транспорт, ошибки, разбор ответов и прежний демотранспорт.
- `src/entities/session/api`, `src/entities/product/api`, `src/entities/cart/api` — авторизация, каталог, карточки, акции и корзина по PHP-контрактам.
- `src/features/auth-login`, `src/features/manage-cart`, `src/pages/login`, `src/pages/catalog` — прежние сценарии и экраны; текущие маршруты их не используют.
- [docs/backend-api.md](docs/backend-api.md) — аудит 37 PHP-обработчиков и их ограничений.

`VITE_API_BASE_URL`, `VITE_DEMO_MODE` и `API_PROXY_TARGET` относятся к сохранённой интеграции. Изменение этих параметров **не переключает новые ERP/WMS-экраны на PHP**. Сервер и SQL без работающего бэкенда не проверялись; дальнейшее подключение потребует сопоставить серверные возможности с моделью заказов, ролей и складских заданий прототипа.

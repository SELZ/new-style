# Архитектура фронтенда

Приложение организовано по Feature-Sliced Design: зависимости направлены от сборки приложения и страниц к сценариям, бизнес-сущностям и общим модулям. Разделение ответственности и порядок слоев соответствуют [официальному описанию слоев FSD](https://feature-sliced.design/docs/reference/layers).

| Слой | Слайсы / сегменты | Ответственность |
| --- | --- | --- |
| `app` | вход в приложение, стили | Сборка экранов, запуск React и глобальные стили. `src/main.tsx` вызывает экспорт из `app/index.ts`; ReactDOM находится в `app/entrypoint.tsx`. |
| `pages` | `login`, `catalog` | Компоновка экрана входа и каталога; навигация по категориям, поиск и фильтры каталога. |
| `widgets` | `cart-drawer`, `product-details`, `site-header`, `site-footer` | Крупные блоки интерфейса: корзина, подробности товара, шапка и подвал. |
| `features` | `auth-login`, `manage-cart` | Вход в учетную запись и операции с серверной корзиной. |
| `entities` | `product`, `cart`, `session` | Типы, доступ к данным и отображение бизнес-сущностей без композиции экранов. |
| `shared` | `api`, `config`, `ui/icon`, `ui/brand` | Общий транспорт и его режимы, настройка окружения, независимые элементы интерфейса. |

`app` и `shared` состоят из технических сегментов; `pages`, `widgets`, `features` и `entities` — из независимых слайсов предметной области. Внутреннее разбиение слайса на `ui`, `model`, `api` определяется его задачами. Перенос каталогов не меняет PHP-контракт, параметры запросов и поведение демонстрационного режима; контракт API описан отдельно в [backend-api.md](./backend-api.md).

## Правила зависимостей

```text
app → pages → widgets → features → entities → shared
```

Стрелки задают порядок: разрешено пропускать промежуточные слои. Например, страница может обращаться непосредственно к сущности. Внутри одного слайса файлы используют друг друга свободно, но два слайса одного слоя друг от друга не зависят. Общая композиция поднимается на слой выше. Импорты из `shared` в любой другой слой запрещены.

У каждого слайса есть публичный `index.ts`. Внешний код импортирует этот файл, например `../../entities/product/index.ts`, а не `../../entities/product/model/types.ts`. Внутри самого слайса разрешены прямые относительные импорты. Такое ограничение скрывает внутреннее устройство и соответствует [рекомендации FSD о публичных API](https://feature-sliced.design/docs/reference/public-api).

Для Shared проект применяет отдельные публичные точки входа к самостоятельным модулям: `shared/api/index.ts`, `shared/config/index.ts`, `shared/ui/icon/index.ts`, `shared/ui/brand/index.ts`. Они могут зависеть друг от друга через эти точки входа. Единого общего `shared/index.ts` или `shared/ui/index.ts`, экспортирующего все модули сразу, не требуется. `app` может свободно связывать свои внутренние сегменты; `main.tsx` имеет только одну локальную зависимость — `app/index.ts`.

CSS принадлежит тому же модулю, что и компонент; глобальные стили находятся в `app/styles`. Импорт стилей не должен обходить границы слоев и слайсов. URL шрифтов и изображений внутри CSS являются ссылками на ресурсы, а не зависимостями бизнес-модулей.

## Автоматическая проверка

[tests/architecture.test.ts](../tests/architecture.test.ts) входит в общий запуск:

```sh
npm test
```

Отдельный запуск:

```sh
node --test tests/architecture.test.ts
```

Проверка разбирает `.ts` и `.tsx` через AST TypeScript, включая обычные и типовые импорты, реэкспорты, `import()` и CommonJS-вызовы `require()`. Для локальных путей проверяется наличие файла, направление зависимости и использование публичного API. Динамический импорт с вычисляемым путем отклоняется, поскольку его зависимости нельзя проверить статически. В CSS проверяются `@import`; комментарии и `url()` ресурсов не рассматриваются как импорты модулей.

Также проверяется наличие публичных точек входа и отсутствие прежних `src/components`, `src/hooks`, `src/api`, `src/data` и корневых файлов интерфейса. Небольшие положительные и отрицательные примеры отдельно проверяют, что валидатор действительно обнаруживает импорт вверх, связь соседних слайсов, обход `index.ts`, отсутствующий файл и нарушение границы bootstrap.

Это проверка структуры зависимостей. Она дополняет TypeScript-сборку, проверки контракта запросов и демонстрационного режима; успешный архитектурный тест сам по себе не подтверждает работоспособность интерфейса или PHP-сервера.
